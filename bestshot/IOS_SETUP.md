# BestShot iOS

## 統合元

- GitHub: `TakuEnjoy/BestShot`, `origin/v2-redesign`
- 2026-10-11に取得した最新コミット: `89d4296`（Improve mode-aware photo grouping, embedding cache, and review UI）
- iOS固有のネイティブ顔解析とONNX設定を維持し、v2のモード別グループ判定、キャッシュ、人物レビュー画面を統合。

## ビルド

iOS 15.5以上。Flutter/Dartの要件は `pubspec.yaml` に従います。Xcode、CocoaPodsが必要です。

```sh
cd bestshot
flutter pub get
flutter analyze
python3 scripts/run_flutter_tests.py
flutter build ios --release --no-codesign
open ios/Runner.xcworkspace
```

実機へのインストール時はRunnerのSigning & Capabilitiesで開発チームを設定し、接続したiPhone/iPadを選択してください。署名なしビルドだけでは実機にインストールできません。

テスト用スクリプトは解決済みONNXパッケージのmacOSライブラリをテストプロセスに読み込ませます。iOSアプリ本体の設定は変更しません。外部画像データが必要なテストは、データが未配置の場合にスキップされます。

OpenCVのネイティブライブラリに合わせて最小OSを15.5に統一しています。macOS上のFlutterテストでは、Xcode 27が依存パッケージの古いmacOSターゲットを拒否する問題を避けるため、OpenCVの生成にUnix Makefilesを使用します。既存のXcode形式のCMakeキャッシュがある場合は `flutter clean` の後に再実行してください。

## iOSでの操作

- **写真ライブラリ**: アクセス許可後、アルバムを選択して新しい写真からバッチ上限まで読み込みます。限定アクセスでは許可した写真だけが対象です。「アクセスを許可する写真を変更」で選択を変更できます。
- **HEIC/HEIF**: ライブラリではPhotoKitのJPEGプレビューを使用します。「ファイル」内のHEIF画像はImageIOで向き補正したJPEGへ変換して解析します。
- **人物モード**: Core Imageで顔・目の開閉を検出します。目を検出できなかった場合は「開いている」と判定しません。顔枠は解析時の画像サイズを保持し、ルーペで解像度が変わっても同じ位置に表示します。
- **フォルダー**: 「ファイル」のフォルダーピッカーを使用し、アプリ起動中は選択したフォルダーのセキュリティスコープを保持します。アプリ再起動後は再選択してください。
- **削除**: ライブラリ写真はPhotoKit経由で削除します。フォルダー写真は元フォルダーの `BestShot Trash/photo_…/` に退避し、完全削除しません。復元する場合は「ファイル」で写真を元のフォルダーへ戻してください。この退避フォルダーは再スキャンの対象外です。
- **仕分け**: フォルダーから取り込んだ写真の移動・コピーに対応します。ライブラリ写真のアルバム間移動には対応していません。

## 実機で確認する項目

ビルド・自動テストでは、実際のPhotoKit権限画面、iCloudダウンロード、外部ファイルプロバイダーの挙動までは検証できません。

1. 写真アクセスを「すべて」「一部」「許可しない」に切り替え、表示と再選択を確認。
2. iCloud上の写真、縦向きHEIC、RAW/JPEGを取り込み、標準／人物モードでグループ化。
3. 顔枠、目つぶり判定、ルーペ拡大、ベスト選択と削除候補の切り替えを確認。
4. ライブラリ削除のOS確認をキャンセルして、写真が画面に残ることを確認。
5. ファイル退避後、`BestShot Trash` から復元できることを確認。
6. iPhoneのノッチ／Dynamic Island、iPadの縦横表示を確認。

ライブラリの初期解析には長辺1920pxのプレビューとPhotoKitの撮影日時を使用します。絞り・ISOなどのEXIF詳細はフォルダー取り込み時に取得します。瞳ランドマーク単位の鮮鋭度評価は現在のiOSネイティブ検出器では未対応です。

## iOS専用構成

実行ターゲットは `ios/` のみです。不要なプラットフォームのフォルダー、プラットフォーム分岐、旧パッチ・バックアップ、汎用ファイルピッカープラグインを削除しました。フォルダー選択と書き出しは同じネイティブピッカーでアクセス権を保持します。ライブラリのベストショットを書き出す場合はPhotoKitから原本を取得します。

iPadのディスプレイでは192MB、iPhoneでは96MBの画像キャッシュを使用し、OSのメモリ警告で解放します。解析ワーカー上限は3、インポートは通常2・大容量画像1です。プロセスを強制終了する処理はありません。

## v2のソート・選別作業（2026-10-15）

`origin/v2-redesign` の `8a503a4`（Add review sessions, manual grouping, protection, and sorting）を取り込みました。グループ順と写真順は一覧の横スクロール可能なツールバー、グループ内の写真順は詳細画面で変更できます。

日時、枚数、要確認、おすすめ、ファイル名、ポートレートの被写体グループ・顔の写り順に対応します。選別・保護・グループ編集・手動保存／再開も同じ作業状態を共有します。操作と仕様は [選別・並べ替え](docs/review-workflow.md) を参照してください。

写真ライブラリのファイル名順はPhotoKitの元の名前を使います。保存・再開はiOSの文書ピッカーとフォルダーブックマークを利用し、他OS用のファイルピッカー依存は追加していません。

統合後の検証: 静的解析の指摘なし。自動テスト91件成功、外部写真データ未配置の2件をスキップ。iOS 15.5以降の署名なしリリースビルド成功（51.6MB）。新しい選別画面は320pt幅でも操作できることをテスト済みです。実機の文書ピッカー・フォルダーブックマーク復元は未検証です。
